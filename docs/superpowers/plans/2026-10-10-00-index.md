## 2. Repo-wide conventions

### 2.1 Language and modules

- TypeScript, strict, ESM everywhere (`"type": "module"`).
- `tsconfig.base.json`: `target` and `lib` ES2024, `module`/`moduleResolution` `NodeNext`, `strict`,
  `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `isolatedModules`,
  `skipLibCheck`, `customConditions: ["@hydra/source"]`.
- `erasableSyntaxOnly` forbids `enum`, `namespace`, and constructor parameter properties. Use `as const`
  objects and normal class fields. Thus `scripts/*.ts` run with the type stripping of Node.js 24.
- Server and shared source files import each other with `.js` extensions (`./config/index.js`).
- `@hydra/web` overrides: `module` `ESNext`, `moduleResolution` `Bundler`, `jsx` `react-jsx`, DOM libs.
- Internal packages export source for development and `dist` for production:
  ```json
  "exports": { ".": { "@hydra/source": "./src/index.ts", "types": "./dist/index.d.ts", "default": "./dist/index.js" } }
  ```
  Vitest, Vite, and `tsx` use the `@hydra/source` condition. Production uses `dist`.
- Server production: `tsc -p tsconfig.build.json` to `dist/`, then `node dist/main.js`. Development:
  `tsx watch --conditions=@hydra/source src/main.ts` (spec section 11.7).

### 2.2 Tests and commands

| Command | Use |
|---|---|
| `pnpm install --frozen-lockfile` | Install (CI and Docker) |
| `pnpm test` | All unit and integration tests (Vitest projects) |
| `pnpm --filter @hydra/server test` | Tests of one package |
| `pnpm --filter @hydra/server exec vitest run src/crypto/subkeys.test.ts` | One test file |
| `pnpm lint` | ESLint (flat config, typescript-eslint) and `prettier --check` |
| `pnpm typecheck` | `tsc --noEmit` in each package |
| `pnpm build` | Build all packages |
| `node scripts/check-repo.ts` | Pinning and config-parity check (spec section 3.4.7) |

- Unit tests are next to the code: `src/**/*.test.ts` (`.test.tsx` in web).
- Server integration tests: `packages/server/test/integration/**/*.test.ts`.
- Server test helpers: `packages/server/test/helpers/*.ts` (section 5.12).
- Prettier: `printWidth` 100, `singleQuote` true, `semi` true, `trailingComma` `all`.

### 2.3 Dependencies

- Exact versions only (spec section 3.4). pnpm enforces the 7-day minimum release age
  (`minimumReleaseAge: 10080`). A plan writes the exact version that `npm view` shows as the newest
  release published on or before 2026-10-03.
- Use the libraries of spec section 3.4.8 and dev tools (TypeScript, ESLint, typescript-eslint,
  Prettier, Vitest, tsx, drizzle-kit, Testing Library, jsdom, `@vitejs/plugin-react`,
  `@tailwindcss/vite`, `eslint-plugin-react-hooks`). Official Fastify plugins are permitted only where
  a plan gives the reason (`@fastify/static` for the dashboard build).
- Do not add other runtime dependencies. Write small helpers in the repo (ULID, cookies, SSE, rate
  limiter).
- A dependency with an install script needs an `allowBuilds` entry with a reason comment (spec rule 6).

### 2.4 Design rules

- Dependency injection: each service gets a `deps` object. No global singletons, except in `main.ts`.
- Time comes only from `Clock` (section 5.2). Tests use `FakeClock`.
- Each module owns its database queries on the shared Drizzle schema (`db/schema.ts`). There is no
  shared repository layer.
- Services throw `HydraError` (section 5.2). Only `api/errors.ts` turns errors into HTTP responses.
- better-sqlite3 is synchronous. Database functions are synchronous. Password hashing and Kubernetes
  calls are asynchronous.
- Logs: pino through the Fastify logger, with the redact paths of spec section 14.

## 3. No commits: the checkpoint step

`AGENTS.md` rule 1 forbids commits. Instructions in plans and skills do not count as a request. Thus:

- No plan has a "Commit" step. The last step of each task is a **Checkpoint** step:
  ```markdown
  - [ ] **Step N: Checkpoint**
    Run: `pnpm lint && pnpm typecheck && pnpm --filter <package> test`
    Expected: all pass.
    Do not commit (AGENTS.md rule 1). Report the changed and the new files to the controller.
  ```
- The controller stages the files of a task with `git add` after its reviews pass. The changes of the
  task under review are the unstaged changes and the untracked files (`git status --porcelain`,
  `git diff`). Staging is not a commit.

### 5.6 `events/` (plan 02)

```ts
export type HydraEvent =
  | { type: 'session.state'; sessionId: string; state: SessionState; previous: SessionState; errorReason: string | null }
  | { type: 'session.activity'; sessionId: string; agentActivity: AgentActivity }
  | { type: 'token.revoked'; tokenId: string; sessionId: string }
  | { type: 'rights.changed'; userId: string }
  | { type: 'login.ended'; userId: string; loginSessionIds: string[] }
  | { type: 'audit'; event: AuditEvent };
export class EventBus {
  constructor(logger: Logger);
  publish(event: HydraEvent): void;                       // synchronous; a handler error is logged, not thrown
  subscribe<T extends HydraEvent['type']>(type: T, handler: (event: Extract<HydraEvent, { type: T }>) => void): () => void;
}
```

The module that causes an event publishes it. `session.state` and `token.revoked` also have audit
events: the owner module writes the audit event and publishes the bus event.

```ts
  revokeAllCreatedBy(userId: string): void;
  isValid(tokenId: string): boolean;                                       // spec section 6.6 conditions

}
```

- `admin.session_access` rule: `requireSession` writes it when the right comes only from the global
  admin role, for all requests except `GET /api/sessions`, `GET /api/sessions/:sid`,
  `GET /api/sessions/:sid/members`, and `GET /api/events`.
- Common passwords: `src/auth/common-passwords.txt`, from SecLists
  `Passwords/Common-Credentials/10-million-password-list-top-100000.txt` at a pinned commit (plan 03
  records the commit and the SHA-256). The check is case-insensitive.

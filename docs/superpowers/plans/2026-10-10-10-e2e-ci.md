# Hydra Browsers v1 — Plan 10: E2E Tests and CI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@hydra/e2e` (Playwright end-to-end tests of the main flow, the security tests, and the long MCP stream test on the k3d cluster), add the e2e jobs to CI and a nightly workflow, and write the manual load check procedure.

**Architecture:** The tests run on the host against the k3d cluster that `scripts/dev-cluster.sh` (plan 08) creates, with the gateway in the cluster (spec section 11.7). A Playwright **setup project** checks the cluster, creates the first admin with the gateway CLI through `kubectl exec -i` (the password goes to stdin), creates a viewer and an outsider through the API, and saves their login sessions. The tests use the dashboard UI where STYLE.md section 7 gives the texts, the dashboard API (Playwright `APIRequestContext`, with the CSRF `Origin` header) for the actions without such texts, the MCP TypeScript SDK as the agent, a small `node:http` Streamable HTTP client for exact status codes and stream lifetimes, and `kubectl`/`docker` for the Kubernetes objects, the profile folder inside the k3d node, network probes from a session pod, and a copy of the gateway database. Pure helpers have Vitest unit tests that run without a cluster.

**Tech Stack:** TypeScript (ESM, strict), `@playwright/test` 1.63.0, `@modelcontextprotocol/sdk` 1.32.0, Vitest 5.0.3, Node.js 24.21.0 (`node:http`, `node:net`, `node:sqlite`), kubectl, Docker, k3d, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-10-hydra-browsers-design.md`, sections 1.1, 15.3, 15.4, 15.5 (and the sections that the tests check: 3.4, 5.2, 6.4 to 6.6, 7.3, 7.9, 8.2, 8.3, 8.6, 8.7, 9.2 to 9.4, 10.2, 11.3, 11.4). Index: `docs/superpowers/plans/2026-10-10-00-index.md`.

## Review Focus

1. **A rerun on the same cluster after a failed or cancelled run.** Old `e2e-*` sessions still hold media ports and the `HYDRA_MAX_RUNNING` capacity. Expected: the setup project deletes them and waits until they are gone; the users are new in each run. Pinned by the `deleteLeftoverSessions` unit test in Task 2.
2. **A blocked navigation whose error page interrupts the next `browser_navigate`.** Chromium still commits `chrome-error://chromewebdata/` when the next navigation starts (seen with Playwright MCP 0.0.83). Expected: the helper repeats only this error, at most 3 times; other errors fail at once. Pinned by the `navigate` unit tests in Task 2.
3. **A gateway that buffers the response headers of an idle MCP event stream** (spec section 8.2 step 6 says "without a buffer"). Expected: the test fails with "No response headers …" after 30 s instead of a hang until the test timeout. Pinned by the `openGetStream` unit test in Task 2.
4. **A poll callback that throws** (live iframe not loaded yet, request error). `expect.poll` does not retry a callback that throws (checked with Playwright 1.63.0). Expected: the helpers return a value (`null`, status `0`) and the poll keeps polling. Pinned by the `liveStatus` unit test in Task 2.
5. **An audit `ip` in IPv4-mapped IPv6 form** (`::ffff:172.18.0.3`, what Node.js gives for IPv4 clients on a dual-stack socket). Expected: the address is normalized before the CIDR checks. Pinned by the `normalizeIp` unit tests in Task 1.

## Spec deviations

1. **"Client address" on k3d (spec section 15.3, last security test).** The test runner connects to `127.0.0.1`, but on k3d the traffic reaches the node through the k3d load balancer container or the Docker port proxy, so the node sees an address of the k3d Docker network, not `127.0.0.1`. The test therefore checks that the `ip` of each `auth.login` event of the admin is in the k3d Docker network (or equal to `HYDRA_E2E_CLIENT_IP` if set), and not in the pod CIDR `10.42.0.0/16`, not in the Service CIDR `10.43.0.0/16`, and not the node address. This keeps the meaning of the spec (the address of the peer that connects to the node, not an internal hop). The API has no route for audit events without a session, so the test reads the events from a backup of the gateway database (`hydra db backup`, then `docker cp` out of the k3d node).

## Index issues

1. **No contract for the dev environment that the e2e tests use.** Section 5 does not fix the dev URLs, the k3d context and network names, the gateway object names, or the test site (namespace, Service, port, routes, cookie name and attributes, redirect parameter). This plan puts its assumptions in one file, `packages/e2e/src/env.ts`, and checks them against the files of plans 01 to 09 in Task 1 Step 1. Proposal: a section 5.13 "Dev environment and test site (plans 08 and 10)" with the values of the table "Inputs from plans 01 to 09" below.
2. **CLI stdin contract (plans 03 and 10).** Section 5 does not say how `hydra user create --admin --email <e>` reads the password when stdin is not a terminal, or that the first admin has `mustChangePassword: false`. This plan sends one line to stdin (`kubectl exec -i`, no `-t`) and expects exit code 0 and `mustChangePassword: false`.
3. **`scripts/versions.sh` names (plans 01, 08, 10).** Section 5 does not fix the variable names; plan 01 (its Index issue 7) defines `K3D_VERSION` (`v5.9.0`), which this plan reads. The SHA-256 values of the k3d binary have no place in `scripts/versions.sh` (plan 01 owns it), so this plan keeps them in `packages/e2e/scripts/install-k3d.sh`. Proposal: `K3D_SHA256_<OS>_<ARCH>` variables next to `K3D_VERSION`, so that one Renovate change updates both.
4. **Response shapes that section 5.1 leaves open.** The list wrapper of `GET /api/sessions` (array or object) and the status of create routes (200 or 201). The helpers accept an array or `{ sessions }`, and any 2xx.
5. **UI contract beyond STYLE.md section 7.** The tests also rely on: the routes `/login`, `/sessions/:sid/live`, `/sessions/:sid/tokens`, `/sessions/:sid/activity` (spec section 3.2); a login form with one text field, one password field, and Enter to submit; a live iframe whose `src` starts with `<HYDRA_LIVE_URL>/s/<sid>/`; table rows (`role=row`) that show the token name and prefix (Tokens) and the raw audit `kind` and `tool` (Activity); a sidebar item that shows the session name as text and opens that session in the same browser tab. Proposal: add these to STYLE.md section 7 or to index section 5.
6. **File ownership.** `pnpm install` for the new package changes `pnpm-lock.yaml` (not listed for plan 10, as for the other plans that add packages). Plan 01 owns `.gitignore` (it ignores `node_modules/`, `dist/`, `coverage/`, `.data/`, `.env`) and `.prettierignore` (it skips only Markdown and the two pnpm files), and Prettier does not read nested `.gitignore` files (checked with Prettier 3.9.9). Playwright output inside the package would make `pnpm lint` fail, so this plan writes all run outputs outside the repository (`HYDRA_E2E_OUTPUT_DIR`). A composite action or a reusable workflow would remove the repeated setup steps of the three e2e jobs, but `.github/actions/**` and other workflow files are not in the ownership of plan 10.
7. **Checkpoint command (index section 3).** The checkpoint runs `pnpm --filter <package> test`. Plan 01 makes `test` of `@hydra/e2e` the Playwright run of the root `pnpm e2e`, which needs Docker + k3d, and forbids a `vitest.config.ts` in the package. Thus the checkpoints of this plan run `pnpm --filter @hydra/e2e run test:unit` (the unit tests of the helpers, config `vitest.unit.config.ts`, outside the root projects glob `packages/*/vitest.config.ts`). The `e2e` CI job also runs them.
8. **`hydra-mcp` image (plan 08).** The network test runs `node -e` in container `mcp` of a session pod, so the image must keep `node` on `PATH` (spec section 11.1: base `node:24.21.0-slim`).

## How to run the steps that need Docker + k3d

The controller runs these steps when Docker runs and the pinned k3d is installed:

1. Start Docker Desktop and wait until `docker info` works.
2. Install k3d once (Task 2 creates the script): `bash packages/e2e/scripts/install-k3d.sh "$HOME/.local/bin"`, and put `$HOME/.local/bin` on `PATH`. Expected last lines: `k3d version v5.9.0` and a `k3s version` line.
3. Create the cluster: `bash scripts/dev-cluster.sh` (plan 08). Expected: exit code 0, and `kubectl --context k3d-hydra-dev get nodes` shows one node with `Ready`.
4. Install the Playwright browser once: `pnpm --filter @hydra/e2e exec playwright install chromium`.
5. After a rebuild of the images, run `bash scripts/dev-cluster.sh` again. To start from zero: `k3d cluster delete hydra-dev`.

`packages/e2e/src/net.test.ts`:

```ts
import { describe, expect, it } from 'vitest';
import { ipInCidr, normalizeIp } from './net.js';

describe('normalizeIp', () => {
  it('removes the IPv4-mapped IPv6 prefix', () => {
    expect(normalizeIp('::ffff:172.18.0.3')).toBe('172.18.0.3');
    expect(normalizeIp('::FFFF:10.42.0.7')).toBe('10.42.0.7');
  });

  it('keeps other addresses', () => {
    expect(normalizeIp('172.18.0.3')).toBe('172.18.0.3');
    expect(normalizeIp('::1')).toBe('::1');
    expect(normalizeIp('2001:db8::1')).toBe('2001:db8::1');
  });
});

describe('ipInCidr', () => {
  it('finds addresses inside the k3s pod CIDR', () => {
    expect(ipInCidr('10.42.0.1', '10.42.0.0/16')).toBe(true);
    expect(ipInCidr('10.42.255.254', '10.42.0.0/16')).toBe(true);
  });

  it('rejects addresses outside the CIDR', () => {
    expect(ipInCidr('10.43.0.1', '10.42.0.0/16')).toBe(false);
    expect(ipInCidr('172.18.0.3', '10.42.0.0/16')).toBe(false);
```

```ts
import { BlockList, isIP } from 'node:net';

/** Removes the IPv4-mapped IPv6 prefix: '::ffff:172.18.0.3' becomes '172.18.0.3'. */
export function normalizeIp(ip: string): string {
  const prefix = '::ffff:';
  if (ip.toLowerCase().startsWith(prefix) && isIP(ip.slice(prefix.length)) === 4) {
    return ip.slice(prefix.length);
  }
  return ip;
}

/** True if the IPv4 address is inside the IPv4 CIDR. IPv6 addresses and bad input give false. */
export function ipInCidr(ip: string, cidr: string): boolean {
  const [base, bits] = cidr.split('/');
  if (base === undefined || bits === undefined || isIP(base) !== 4 || isIP(ip) !== 4) {
    return false;
  }
  const list = new BlockList();
  list.addSubnet(base, Number(bits), 'ipv4');
  return list.check(ip, 'ipv4');
}
```

```ts
/** Returns the data of each event of a text/event-stream body. Data lines are joined with '\n'. */
export function parseSseData(body: string): string[] {
  const events: string[] = [];
  for (const block of body.replace(/\r\n?/g, '\n').split('\n\n')) {
    const data = block
      .split('\n')
      .filter((line) => line.startsWith('data:'))
      .map((line) => line.slice('data:'.length).replace(/^ /, ''));
    if (data.length > 0) {
      events.push(data.join('\n'));
    }
  }
  return events;
}
```

```ts
export interface ToolOutcome {
  isError: boolean;
  text: string;
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null;
}

/** Returns the error flag and the joined text parts of a tools/call result. */
export function toToolOutcome(result: unknown): ToolOutcome {
  if (!isRecord(result)) {
    throw new Error('The tools/call result is not an object');
  }
  const parts: unknown[] = Array.isArray(result.content) ? (result.content as unknown[]) : [];
  const text = parts
    .map((part) =>
      isRecord(part) && part.type === 'text' && typeof part.text === 'string' ? part.text : '',
    )
    .filter((partText) => partText !== '')
    .join('\n');
  return { isError: result.isError === true, text };
}

/** Parses the JSON value after "### Result" in a browser_evaluate text (Playwright MCP 0.0.83). */
export function parseEvaluateResult(text: string): unknown {
  const marker = '### Result\n';
  const start = text.indexOf(marker);
  if (start === -1) {
    throw new Error(`No "### Result" section in: ${text}`);
  }
  const rest = text.slice(start + marker.length);
  const end = rest.indexOf('\n### ');
  return JSON.parse(end === -1 ? rest : rest.slice(0, end)) as unknown;
}
```

```ts
import { spawn } from 'node:child_process';
import { E2E } from './env.js';

export interface RunResult {
  code: number;
  stdout: string;
  stderr: string;
}

export interface RunOptions {
  /** Written to stdin, then stdin closes. */
  input?: string;
  timeoutMs?: number;
}

/** Runs a command without a shell. Never rejects for a non-zero exit code. */
export function run(
  command: string,
  args: readonly string[],
  options: RunOptions = {},
): Promise<RunResult> {
  return new Promise((resolve, reject) => {
    const child = spawn(command, args, {
      stdio: ['pipe', 'pipe', 'pipe'],
      timeout: options.timeoutMs ?? 120_000,
    });
    let stdout = '';
    let stderr = '';
    child.stdout.setEncoding('utf8').on('data', (chunk: string) => {
      stdout += chunk;
    });
    child.stderr.setEncoding('utf8').on('data', (chunk: string) => {
      stderr += chunk;
    });
    child.on('error', reject);
    child.on('close', (code, signal) => {
      resolve({ code: code ?? (signal === null ? 1 : 128), stdout, stderr });
    });
    child.stdin.end(options.input ?? '');
  });
}

/** Runs a command and returns stdout. Rejects for a non-zero exit code. Never prints the input. */
export async function runOk(
  command: string,
  args: readonly string[],
  options: RunOptions = {},
): Promise<string> {
  const result = await run(command, args, options);
  if (result.code !== 0) {
    throw new Error(
      `${command} ${args.join(' ')} exited with ${result.code}:\n${result.stderr}${result.stdout}`,
    );
  }
  return result.stdout;
}

/** kubectl against the k3d cluster only, never against the current context. */
export function kubectl(args: readonly string[], options: RunOptions = {}): Promise<string> {
  return runOk('kubectl', ['--context', E2E.kubeContext, ...args], options);
}

export function kubectlResult(
  args: readonly string[],
  options: RunOptions = {},
): Promise<RunResult> {
  return run('kubectl', ['--context', E2E.kubeContext, ...args], options);
}

export function docker(args: readonly string[], options: RunOptions = {}): Promise<string> {
```

```ts
export class HydraApi {
  readonly request: APIRequestContext;

  constructor(context: APIRequestContext) {
    this.request = context;
  }

  /** The Origin header passes the CSRF check of spec section 6.4. */
  static async create(storageState?: string): Promise<HydraApi> {
    const context = await request.newContext({
      baseURL: E2E.publicUrl,
      extraHTTPHeaders: { origin: new URL(E2E.publicUrl).origin },
      ...(storageState === undefined ? {} : { storageState }),
    });

  static async login(email: string, password: string): Promise<HydraApi> {
    const api = await HydraApi.create();
    await api.ok('POST', '/api/auth/login', { email, password });
    return api;
  }

  /** Any request. A request that is not GET always has a JSON body (`{}` if there is no data). */
  async call(
    method: Method,
    path: string,
    data?: unknown,
    options: { timeoutMs?: number } = {},
  ): Promise<ApiResult> {
    const response = await this.request.fetch(path, {
      method,
      ...(method === 'GET' ? {} : { data: data ?? {} }),
      ...(options.timeoutMs === undefined ? {} : { timeout: options.timeoutMs }),
    });
    const text = await response.text();
    let json: unknown = null;
    if (text !== '') {
      try {
        json = JSON.parse(text) as unknown;
      } catch {
        json = null;
      }
    }
    return { status: response.status(), text, json };
  }

  /** A request that must succeed (2xx). Returns the parsed body. */
  async ok<T>(method: Method, path: string, data?: unknown): Promise<T> {
    const result = await this.call(method, path, data);
    if (result.status < 200 || result.status > 299) {
      throw new Error(`${method} ${path} returned ${result.status}: ${result.text}`);
    }
    return result.json as T;
  }

    return this.ok<Me>('GET', '/api/auth/me');
  }

    await this.ok('POST', '/api/auth/password', { current, new: next });

      role: 'member',

    return this.ok<SessionResource>('GET', `/api/sessions/${sid}`);
  }

      throw new Error(`GET /api/sessions returned no list: ${JSON.stringify(body)}`);

  /** Polls GET /api/sessions/:sid every second. Fails at once on the state "error". */
  async waitForState(
    sid: string,
    state: SessionState,
    timeoutMs: number,
  ): Promise<{ session: SessionResource; elapsedMs: number }> {
    const started = Date.now();
    for (;;) {
      const session = await this.getSession(sid);
      const elapsedMs = Date.now() - started;
      if (session.state === state) {
        return { session, elapsedMs };
      }
      if (session.state === 'error') {
        throw new Error(`Session ${sid} is in the state error: ${session.errorReason ?? ''}`);
      }
      if (elapsedMs > timeoutMs) {
        throw new Error(`Session ${sid} is ${session.state}, not ${state}, after ${timeoutMs} ms`);
      }
      await sleep(1_000);
    }
  }

  /** Polls until GET /api/sessions/:sid returns 404. */
  async waitForGone(sid: string, timeoutMs: number): Promise<void> {
    const started = Date.now();
    for (;;) {
      const result = await this.call('GET', `/api/sessions/${sid}`);
      if (result.status === 404) {
        return;
      }
      if (Date.now() - started > timeoutMs) {
        throw new Error(`Session ${sid} still exists after ${timeoutMs} ms: ${result.text}`);
      }
      await sleep(1_000);
    }
  }

  createToken(sid: string, name: string): Promise<CreateTokenResponse> {
    return this.ok<CreateTokenResponse>('POST', `/api/sessions/${sid}/tokens`, {
      name,
      expiresInDays: 1,
    });
  }

  async revokeToken(sid: string, tokenId: string): Promise<void> {
    await this.ok('DELETE', `/api/sessions/${sid}/tokens/${tokenId}`);
  }

  audit(sid: string, query: AuditQuery): Promise<AuditPage> {
    const params = new URLSearchParams();
    for (const [key, value] of Object.entries(query)) {
      if (value !== undefined) {
        params.set(key, String(value));
      }
    }
    return this.ok<AuditPage>('GET', `/api/sessions/${sid}/audit?${params.toString()}`);
  }

  addMember(sid: string, email: string, role: MemberRole): Promise<Member> {
    return this.ok<Member>('POST', `/api/sessions/${sid}/members`, { email, role });

    await this.request.storageState({ path });
  }

  async dispose(): Promise<void> {
    await this.request.dispose();
  }
}
```

```ts
const INTERRUPTED = 'is interrupted by another navigation';

export async function navigate(client: Client, url: string): Promise<ToolOutcome> {
  let outcome = await callTool(client, 'browser_navigate', { url });
  for (
    let retry = 0;
    retry < 3 && outcome.isError && outcome.text.includes(INTERRUPTED);
    retry += 1
  ) {
    await sleep(1_000);
    outcome = await callTool(client, 'browser_navigate', { url });
  }
  if (outcome.isError) {
    throw new Error(`browser_navigate ${url} failed: ${outcome.text}`);
  }
  return outcome;
}
```

```ts
import http from 'node:http';
import https from 'node:https';
import { LATEST_PROTOCOL_VERSION } from '@modelcontextprotocol/sdk/types.js';
import { parseSseData } from './sse.js';

/**
 * A small Streamable HTTP client on node:http. The tests use it where they need the exact status,
 * the exact body, or the life of one MCP stream. node:http has no body timeout, so a stream can stay
 * open for the 10 min of the long test.
 */

export interface RawResponse {
  status: number;
  headers: http.IncomingHttpHeaders;
  body: string;
}

export interface RawMcpSession {
  endpoint: string;
  token: string;
  id: string;
  protocolVersion: string;
}

function send(
  url: URL,
  method: 'GET' | 'POST' | 'DELETE',
  headers: Record<string, string>,
  body?: string,
  headersTimeoutMs = 30_000,
): Promise<http.IncomingMessage> {
  const client = url.protocol === 'https:' ? https : http;
  return new Promise((resolve, reject) => {
    // agent: false gives each request its own connection, so one stream never shares a socket.
    const request = client.request(url, { method, headers, agent: false }, (response) => {
      clearTimeout(timer);
      resolve(response);
    });
    // Only the response headers have a time limit. An open stream has none.
    const timer = setTimeout(() => {
      request.destroy(
        new Error(`No response headers for ${method} ${url.href} after ${headersTimeoutMs} ms`),
      );
    }, headersTimeoutMs);
    request.on('error', (error) => {
      clearTimeout(timer);
      reject(error);
    });
    request.end(body);
  });
}

async function readBody(response: http.IncomingMessage): Promise<string> {
  response.setEncoding('utf8');
  let body = '';
  for await (const chunk of response) {
    body += String(chunk);
  }
  return body;
}

function sessionHeaders(session: RawMcpSession): Record<string, string> {
  return {
    authorization: `Bearer ${session.token}`,
    'mcp-session-id': session.id,
    'mcp-protocol-version': session.protocolVersion,
  };
}

export function initializeMessage(): Record<string, unknown> {
  return {
    jsonrpc: '2.0',
    id: 1,
    method: 'initialize',
    params: {
      protocolVersion: LATEST_PROTOCOL_VERSION,
      capabilities: {},
      clientInfo: { name: 'hydra-e2e-raw', version: '1.0.0' },
    },
  };
}

/** POSTs one JSON-RPC message and reads the whole response. */
export async function mcpPost(
  endpoint: string,
  token: string,
  message: Record<string, unknown>,
  session?: RawMcpSession,
): Promise<RawResponse> {
  const headers: Record<string, string> = {
    authorization: `Bearer ${token}`,
    'content-type': 'application/json',
    accept: 'application/json, text/event-stream',
    ...(session === undefined ? {} : sessionHeaders(session)),
  };
  const response = await send(new URL(endpoint), 'POST', headers, JSON.stringify(message));
  return {
    status: response.statusCode ?? 0,
    headers: response.headers,
    body: await readBody(response),
  };
}

/** The JSON-RPC messages of a response body (application/json or text/event-stream). */
export function rpcMessages(response: RawResponse): unknown[] {
  const type = response.headers['content-type'] ?? '';
  if (type.startsWith('text/event-stream')) {
    return parseSseData(response.body).map((data) => JSON.parse(data) as unknown);
  }
  return [JSON.parse(response.body) as unknown];
}

/** initialize, then notifications/initialized. */
export async function openRawSession(endpoint: string, token: string): Promise<RawMcpSession> {
  const init = await mcpPost(endpoint, token, initializeMessage());
  if (init.status !== 200) {
    throw new Error(`initialize returned ${init.status}: ${init.body}`);
  }
  const id = init.headers['mcp-session-id'];
  if (typeof id !== 'string') {
    throw new Error('initialize returned no Mcp-Session-Id header');
  }
  const first = rpcMessages(init)[0] as { result?: { protocolVersion?: unknown } } | undefined;
  const negotiated = first?.result?.protocolVersion;
  const session: RawMcpSession = {
    endpoint,
    token,
    id,
    protocolVersion: typeof negotiated === 'string' ? negotiated : LATEST_PROTOCOL_VERSION,
  };
  const note = await mcpPost(
    endpoint,
    token,
    { jsonrpc: '2.0', method: 'notifications/initialized' },
    session,
  );
  if (note.status !== 202) {
    throw new Error(`notifications/initialized returned ${note.status}: ${note.body}`);
  }
  return session;
}

export interface McpStream {
  status: number;
  isOpen(): boolean;
  /** Resolves when the stream ends, for any reason. */
  closed: Promise<void>;
  close(): void;
}

/** Opens the GET stream of an MCP session and watches its end. */
export async function openGetStream(
  session: RawMcpSession,
  headersTimeoutMs = 30_000,
): Promise<McpStream> {
  const response = await send(
    new URL(session.endpoint),
    'GET',
    { ...sessionHeaders(session), accept: 'text/event-stream' },
    undefined,
    headersTimeoutMs,
  );
  let open = response.statusCode === 200;
  const closed = new Promise<void>((resolve) => {
    const end = (): void => {
      open = false;
      resolve();
    };
    response.on('end', end);
    response.on('close', end);
    response.on('error', end);
  });
  response.resume();
  return {
    status: response.statusCode ?? 0,
    isOpen: () => open,
    closed,
    close: () => response.destroy(),
  };
}

export async function deleteRawSession(session: RawMcpSession): Promise<number> {
  const response = await send(new URL(session.endpoint), 'DELETE', sessionHeaders(session));
  await readBody(response);
  return response.statusCode ?? 0;
}
```

```ts
import { setTimeout as sleep } from 'node:timers/promises';
import { expect, test } from '../src/fixtures.js';
import { mcpPost, openGetStream, openRawSession } from '../src/mcp-raw.js';
import { mcpEndpoint } from '../src/mcp.js';

const TEN_MINUTES = 10 * 60_000;

// Runs only in the nightly workflow and on pull requests that change deploy/traefik/ or
// scripts/versions.sh (spec section 15.3). The stream carries no data, so any idle timeout on the
// path (Traefik entry point, gateway, undici) would close it.
test(
  'an MCP stream stays open for 10 min through Traefik',
  { tag: '@long' },
  async ({ adminApi, sessionPair }) => {
    test.setTimeout(15 * 60_000);
    const { a } = sessionPair;
    const token = await adminApi.createToken(a.id, 'e2e-long-stream');
    const session = await openRawSession(mcpEndpoint(a.id), token.secret);
    const stream = await openGetStream(session);
    try {
      expect(stream.status).toBe(200);
      const openedAt = Date.now();
      while (Date.now() - openedAt < TEN_MINUTES) {
        await Promise.race([stream.closed, sleep(30_000)]);
        const seconds = Math.round((Date.now() - openedAt) / 1_000);
        expect(stream.isOpen(), `the MCP stream is open after ${seconds} s`).toBe(true);
      }
      // The MCP session still answers after the 10 min.
      const list = await mcpPost(
        session.endpoint,
        session.token,
        { jsonrpc: '2.0', id: 2, method: 'tools/list' },
        session,
      );
      expect(list.status).toBe(200);
      expect(stream.isOpen()).toBe(true);
    } finally {
      stream.close();
      await adminApi.revokeToken(a.id, token.token.id);
    }
  },
);
```

````markdown
# Load check

This is the manual load check of spec section 15.5: on the target EC2 type, run 10 sessions and watch
3 of them as 1080p video streams. Record the CPU and the RAM, then adjust the resource defaults of
spec section 7.4.

Do the check before the first production use, and again after a change of the EC2 type, of Neko, or of
the resource values.

## 1. Before you start

- A host of the target EC2 type, installed with `scripts/setup-k3s.sh`, with the `prod` overlay applied
  and TLS working (spec section 11).
- An admin account (spec section 6.3) and `HYDRA_MAX_RUNNING` at `10` or more.
- No other running sessions: the check needs all 10 media ports.
- On your computer: `curl`, `jq`, and a desktop browser. Three browser windows must fit side by side on
  your screen.
- An SSH session on the host. The commands on the host use `sudo k3s kubectl`, because the kubeconfig of
  k3s has mode `0600` (spec section 11.6).

  sudo k3s kubectl top pods -n hydra-sessions --containers --no-headers |
    awk -v ts="$ts" '{ cpu = $3; mem = $4; sub(/m$/, "", cpu); sub(/Mi$/, "", mem); print ts "\t" $1 "\t" $2 "\t" cpu "\t" mem }' >> load-top.tsv

## 6. Summary

On the host:

```bash
awk -F'\t' -v watched="$(paste -sd ' ' load-watched.txt)" '
  BEGIN { n = split(watched, w, " "); for (i = 1; i <= n; i++) isWatched["session-" w[i] "-0"] = 1 }
  {
    group = (($2 in isWatched) ? "watched" : "idle") "/" $3
    count[group]++; cpuSum[group] += $4; memSum[group] += $5
    if ($4 > cpuMax[group]) cpuMax[group] = $4
    if ($5 > memMax[group]) memMax[group] = $5
  }
  END {
    printf "%-14s %10s %10s %11s %11s\n", "group", "cpu avg m", "cpu max m", "mem avg Mi", "mem max Mi"
    for (g in count) printf "%-14s %10.0f %10.0f %11.0f %11.0f\n", g, cpuSum[g] / count[g], cpuMax[g], memSum[g] / count[g], memMax[g]
  }' load-top.tsv
sudo k3s kubectl get pods -n hydra-sessions \
  -o custom-columns='POD:.metadata.name,RESTARTS:.status.containerStatuses[*].restartCount,LAST:.status.containerStatuses[*].lastState.terminated.reason'
```

Expected: one line for each of `watched/neko`, `watched/mcp`, `idle/neko`, `idle/mcp`, and no restarts
and no `OOMKilled`. Write the numbers in the "Results" table of section 8. From `load-node.txt`, write
the highest node CPU and memory.

## 7. Adjust the resource defaults

Spec section 7.4 gives the defaults: `neko` requests 0.5 CPU / 1.5 Gi, limits 3 CPU / 4 Gi; `mcp`
requests 0.1 CPU / 256 Mi, limits 0.5 CPU / 512 Mi. Compute the new values from the summary:

| Value                 | Rule                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------- |
| `neko` CPU request    | Mean CPU of all 10 `neko` containers: `(3 × watched avg + 7 × idle avg) / 10`, rounded up to 100m         |
| `neko` CPU limit      | 1.5 × `watched/neko` cpu max, rounded up to 500m                                                          |
| `neko` memory request | The larger mem max of `watched/neko` and `idle/neko`, rounded up to 256 Mi                                |
| `neko` memory limit   | 1.5 × that mem max, rounded up to 512 Mi                                                                  |
| `mcp` values          | Keep them, unless a measured value is above its request. The check runs no agent, so the sidecar is idle. |

Then check the capacity with the allocatable values of section 2:

```text
10 × (neko CPU request + mcp CPU request) + 1 CPU (gateway, Traefik, k3s)   ≤ allocatable CPU
10 × (neko memory request + mcp memory request) + 1 Gi                      ≤ allocatable memory
```

- If the capacity check fails, the EC2 type is too small for 10 sessions. Record this, and choose a
  larger type or a lower `HYDRA_MAX_RUNNING`.
- If the node CPU was above 85 %, or a live view froze, the encoders did not get enough CPU. Choose a
  larger type.
- If the new values differ from spec section 7.4: the spec is the source of truth (AGENTS.md rule 2).
  Ask the owner of the spec to change section 7.4, and change the resource values in the pod manifest
  builder (`packages/server/src/orchestrator/manifests/statefulset.ts`) in the same pull request. Update
  the manifest snapshots with
  `pnpm --filter @hydra/server exec vitest run -u src/orchestrator`.
````
